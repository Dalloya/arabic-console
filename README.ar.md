# وحدة التحكم العربية

**[English](README.md)** | العربية

طبقة أوامر عربية أصلية لوحدة التحكم النصية في نواة لينكس (VT).

وحدة التحكم في النواة ترسم نقطة ترميز واحدة في كل خانة، من اليسار إلى اليمين، بلا تشكيل
وبلا خوارزمية اتجاه. كذلك تُسقط العلامات المركبة. هذا المشروع هو ما يلزم لجعل هذا السطح
يعمل بالعربية: خط يحمل الخانات الصحيحة، ومحرك وصل، وعارض يضع السطر بالترتيب البصري،
وجلسة أوامرها كلمات عربية.

ليس توزيعة، وليس طبقة ترجمة. لا شيء هنا يحوّل كلمة عربية إلى كلمة لاتينية.

## ما في هذا المستودع

| المسار | ما هو |
|---|---|
| `src/ar_type.c` | وحدة ترجمة واحدة، ومنها برنامجان: `ar-type` (نافذة الكتابة) و`ar-shell` (جلسة وحدة التحكم، تُبنى بـ `-DAR_TYPE_SHELL=1`) |
| `src/arsh.c` | `شكل` — يشغّل برنامجاً على طرفية افتراضية ويشكّل خرجه العربي لوحدة التحكم |
| `src/ar_*.c` | الأوامر، كل أمر في ملفه |
| `src/ar_type_tables.h` و`src/arsh_marks.h` | بيانات الوصل وخانات العلامات، مولّدة (انظر مستودع `arabic-console-shaper`) |
| `calendars/` | سطر التاريخ الهجري (أم القرى): `تاريخ` |
| `keymap/` | بناء خريطة المفاتيح وفحصها |
| `fonts/` | خط وحدة التحكم 8×16 و16×32 الذي ترسم به هذه الطبقة |
| `oracle/ax170/four_form_table.json` | جدول الوصل الذي يتبعه المشكّل |
| `tools/` | أدوات مرجعية بلغة بايثون، ومعها مجموعة الاختبارات |
| `docs/ARCHITECTURE.md` | لماذا التصميم هكذا، قراراً قراراً |

## كيف يُنفَّذ السطر المكتوب

للجلسة محلّلها ومسار تنفيذها الخاص. ليست بش مع كلمات عربية.

1. **التقطيع.** `sh_parse` تقطع السطر إلى مراحل وكلمات بقواعد تنصيص خاصة بها، وتسجّل
   إعادة التوجيه (`<`، `>`، `>>`، `2>`، `2>>`).
2. **الرفض المبكر.** السطر المشوّه — تنصيص غير مغلق، كلمات أكثر من الحد، إعادة توجيه
   أكثر من الحد — يُرفض كاملاً، بالعربية، قبل أن يُفرَّخ أي شيء. لا تنفيذ جزئي.
3. **حلّ الاسم.** `sh_resolve_stage_name` يطابق الكلمة المكتوبة بأمر، مع حذف الحركات في
   المقارنة فتصير `حرر` و`حرّر` اسماً واحداً، ويجمع الأسماء ذات الكلمتين مثل `اضبط الأذونات`.
4. **المدمجات تبقى في العملية.** `اخرج`، `المسار`، `انتقل`، `حرّر`، `مساعدة`، `شغّل`،
   `متصفح`، `البيئة` تُعالَج داخل الجلسة نفسها: المحرر، والعارض، وجدول المساعدة، والبيئة،
   والخروج.
5. **وما عداها برنامج.** الأنابيب وإعادة التوجيه تعمل عبر منفّذ الجلسة الخاص
   (fork/exec/reap). وتكون القفزة الأخيرة عبر
   `شكل /bin/bash -c '<الكلمات مقتبسة>'` ليعود خرج الابن مشكَّلاً.

## الأوامر

كل أمر ملف تنفيذي حقيقي يُثبَّت في `/usr/local/bin` باسمه العربي. وليس أياً منها غلافاً
لـ `ls` أو `cp` أو `mv` أو `rm`: كل واحد يؤدي عمله بنفسه.

| الأمر | المصدر | ما يفعله |
|---|---|---|
| `اعرض` | `ar_list.c` | عرض محتويات دليل (`opendir`/`readdir`، بلا قشرة) |
| `اطبع` | `ar_print.c` | طبع ملف نصي |
| `أنشئ` | `ar_mkdir.c` | إنشاء دليل |
| `انسخ` | `ar_copy.c` | نسخ |
| `انقل` | `ar_move.c` | نقل |
| `أعد التسمية` | `ar_move.c` | إعادة تسمية |
| `احذف` | `ar_remove.c` | حذف |
| `ابحث` | `ar_find.c` | البحث بالاسم (اسم الملف مطابقاً، ونوع اختياري) |
| `فتّش` | `ar_search.c` | البحث في نص الملفات، بأرقام الأسطر، مطابقة في كل سطر |
| `اعرض الأذونات` | `ar_perm.c` | عرض الأذونات |
| `اضبط الأذونات` | `ar_perm.c` | ضبط الأذونات |
| `حدّث الحزم` | `ar_pkg_update.c` | تحديث الحزم |
| `ثبّت حزمة` | `ar_pkg_install.c` | تثبيت حزمة |
| `أزل حزمة` | `ar_pkg_remove.c` | إزالة حزمة |
| `تاريخ` | `calendars/hijri.c` | سطر التاريخ الهجري والميلادي |

`مساعدة <اسم>` تجيب من جدول ثابت، ولا تختلق سطراً.

## المتطلبات

- `cc` (C99) وPOSIX. بلا مكتبات خارجية.
- خط يحمل خانات العربية — من مستودع `arabic-console-font`، يُحمَّل بـ `setfont`.
- جداول الوصل — مولّدة، ومضمّنة هنا في `src/ar_type_tables.h`.

## البناء

```
./build.sh          # الملفات التنفيذية تخرج في ./out/
```

`build.sh` يبني كل الملفات التنفيذية، ويهيّئ الخط والمصدر حيث تتوقعهما مجموعة الاختبارات،
ثم يشغّل المجموعة. يطبع سطراً لكل اختبار وينتهي بـ `BUILD PASS` أو `BUILD FAIL`.

## الاختبارات، وما لا ينجح منها

| الاختبار | الحال |
|---|---|
| `ar_type_safety_test.c` | ينجح |
| `ar_shell_builtins_test.py` | ينجح |
| `command_marks_test.py` | ينجح |
| `ar_shell_test.py` | **أربعة إخفاقات معروفة** |

الإخفاقات الأربعة كاذبة مقابل بناء الجلسة الحالي، وتفشل بالطريقة نفسها في الشجرة الخاصة
التي استُخرج منها هذا الكود، ولذلك سُمّيت بدل أن تُحذف بصمت:

| التأكيد | ما يتوقعه |
|---|---|
| S1 «مدخل الابن هو /dev/null» | أن يرى الابن مدخلاً مغلقاً |
| S3 «النزول بعد الأحدث يستدعي سطراً فارغاً» | التنقل في التاريخ بعد آخر سطر |
| S4 «المحو الخلفي يحذف وحدة واحدة ويحفظ ضمّة لام-ألف» | محو واحد يزيل وحدة واحدة |
| S5 «عمود المؤشر مشتق من الخانات» | وضع المؤشر بعدّ الخانات لا بعدّ نقاط الترميز |

**محجوب بقرار:** ملف `ar_type_test.py` غير منشور. إنه يؤكد عقد لوحة المفاتيح السابق —
Shift مع مفتاح حركة ينتج `Q`/`W`/`~` لاتينية — بينما العقد المثبَّت يضع الحركات الثماني
على Shift، ويقارن الخرج بايتاً ببايت مع نسخ من بناء أقدم. الاختبار الذي يطلب السلوك
الملغى هو المخطئ، فبقي خارج المستودع بدل نشره أحمر أو إعادة كتابته بصمت.

## الحركات على لوحة المفاتيح

ثماني حركات على Shift، وهي نفس الثماني التي يحملها ROM سخر AX-170:
`16`=U+064E `17`=U+064B `18`=U+064F `19`=U+064C `30`=U+0650 `31`=U+064D `41`=U+0651
`45`=U+0652. والألف الخنجرية U+0670 موجودة في الخط لكنها غير مربوطة بأي مفتاح.

## حدود معروفة، بصراحة

- الهدف وحدة التحكم النصية في النواة. تحت محاكي طرفية تعمل الجلسة في وضع المرور ولا تنفع.
- مُختبَر على آرتش لينكس على عتاد حقيقي، وفي ميزانية خط 512 خانة.
- ابن الأمر يمرّ أخيراً عبر `bash -c`. المحلل والمنفّذ لنا، وقفزة التنفيذ الأخيرة ليست لنا.
- اقتراح جدولي مساعدة (توأم إنجليزي لـ `مساعدة`) دُرس ورُفض. جدول مساعدة واحد، بالعربية.
